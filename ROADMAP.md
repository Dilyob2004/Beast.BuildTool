# Beast BuildTool / Beast SDK — список задач

Обновлено: 27 сентября 2026. Основные платформы — Windows и Android 10+.
iOS пока отложен. Цель UI — собственные C++-приложения с качеством и удобством
уровня Flutter, не запуск существующего Dart-кода.

## 1. Завершить работу над плавностью насыщенных экранов

- [ ] Получить сопоставимые холодные и прогретые замеры одного сценария EcoSbor
  в Release: скролл, отпускание, появление новых элементов. Отдельно учитывать
  подготовку UI, загрузки ресурсов, CPU scheduling и показ кадров.
- [x] Подготавливать глифы ближайших появляющихся элементов в idle: запас
  до половины viewport / 256 логических единиц, мягкая цель 750 μs с паузой
  между глифами, максимум 512 KiB новых/COW страниц за порцию. В кадрах
  drag/animation прогрев не выполняется. См. `Test/EcoSbor/GlyphPrefetch.md`.
- [ ] По замерам сократить повторную подготовку команд, лишние draw calls и
  обработку невидимого содержимого; сохранять тени, clipping и чёткость текста.
- [ ] Добавить нагрузочный сценарий длинного списка; определить необходимость
  виртуализации, не только отсечения отрисовки.
- [ ] Повторить проверки OpenGL/Vulkan, Windows/Android, DPI, safe areas,
  приостановки/возобновления и стабильности памяти после многократного скролла.

Уже сделаны исправления перехода drag → spring, кеш размеров текста и
ограниченный прогрев видимых и ближайших глифов. Это не означает устранение
всех микролагов; замер на физическом Android после последней правки ещё нужен.
Данные: `Test/EcoSbor/TextMetricsOptimization.md`, `Test/EcoSbor/GlyphPrefetch.md`.

## 2. Автоматический hot reload кода проекта

Запрос пользователя: при сохранении корректного кода автоматически обновлять
запущенное приложение; при ошибке сборки сохранять последнюю рабочую версию.
Статус: **первая dev-версия реализована и проверена на Windows и Android-эмуляторе**.
Команда `beast watch`, контракт состояния, ограничения и протокол проверок:
`BuildTool/HotReload.md`. Поддержаны UI-проекты с `BEAST_UI_APPLICATION`.

### Основа и ограничения

В обычной сборке Build.cs задают правила модулей, но GenericProjectBuilder собирает все
исходники Source в один итоговый бинарник: Windows executable / Android shared
library. Отдельный Launch — логическая граница, а не готовая динамическая библиотека.

- [x] Отделить постоянный host/SDK от перезагружаемого кода приложения.
  Продумать единый runtime SDK: нельзя случайно получить независимые копии его
  глобального состояния внутри host и DLL/SO.
- [x] Определить версионируемый контракт модуля: создание/остановка, уничтожение
  объектов своим модулем, восстановление состояния. Проверять совместимость ABI.
- [x] Учесть все зависимые проектные модули и общие заголовки, не только Launch.cpp.
- [x] Добавить watch-режим Beast: debounce сохранений, одна сборка за раз,
  повторная сборка накопившихся изменений, исключение Intermediate/Binaries
  и генерируемых файлов из наблюдения.
- [x] Проверять не только компиляцию, но и линковку, загрузку, контракт и
  инициализацию кандидата до переключения на него.
- [x] При ошибках показывать диагностику и оставлять прежнюю рабочую версию.
  Собирать кандидата отдельно, не перезаписывать загруженный модуль.

### Первый этап: Windows

- [x] Загружать версионированную DLL проекта в постоянный host.
- [x] Переключать модуль в безопасной точке между кадрами. Учитывать фоновые
  задачи, callbacks, захваченные лямбды, virtual methods и GPU-ресурсы: старый
  код нельзя выгружать, пока существуют ссылки или вызовы в него.
- [x] Описать явное сохранение/восстановление состояния сцены: выбранная вкладка,
  прокрутка, поля ввода. Не обещать автоматическое сохранение произвольных
  C++-объектов при изменении расположения полей класса.
- [ ] Для несовместимого изменения SDK/ABI выполнять обозначенный пользователю
  hot restart/full rebuild, не выдавая перезапуск за hot reload.
  Сейчас изменение обнаруживается, требуется вручную перезапустить watch.
  Старые DLL/SO удерживаются до выхода процесса (лимит 32 загрузки); фоновые
  задачи приложения должны останавливаться через QuiesceForReload.

### Второй этап: Android

- [x] Реализовать Debug/dev host и обновляемую SO проекта, сохранив корректный
  lifecycle Activity/surface. Отдельно проверить ограничения загрузчика ОС.
- [x] Доставлять успешно собранный модуль на выбранный эмулятор, проверять
  версию SDK/ABI и результат загрузки; откатывать неудачное переключение.
- [x] Не включать канал доставки/загрузки изменяемого кода в обычный Release APK.

### Приёмочные тесты hot reload

- [ ] Изменение текста, цвета, обработчика кнопки без закрытия окна/Activity.
  Проверены текст/версия и сохранение счётчика кнопки без изменения PID.
- [ ] Compile/link/load/init error: прежняя версия продолжает работать.
  Проверены compile/link/init/ABI ошибки; отдельный сценарий ошибки загрузчика остаётся.
- [ ] Серия быстрых сохранений: не загружается устаревший результат сборки.
- [x] Изменение заголовка обнаруживается корректно; зависимые модули включены в watch.
- [x] Состояние восстанавливается в рамках явного контракта; несовместимые
  изменения явно требуют перезапуска.
- [ ] Многократные reload не оставляют старые callbacks, задачи или утечки.

## 3. Продолжить функциональность UI

- [x] Первый однострочный TextField: UTF-8 scalar editing, курсор/выделение,
  Tab-фокус вместе с кнопками, undo/redo, readOnly и Windows committed input.
  Демо: `Test/TextFieldDemo`. Границы этапа: `BeastSDK/Source/UI/TextField.md`.
- [x] IME composition/session protocol, Android InputConnection, экранная
  клавиатура и IME insets (остаётся матрица физических устройств/IME).
- [x] Clipboard Windows/Android, Ctrl+C/X/V, базовое выделение слова,
  long press, меню действий и touch selection handles.
- [ ] Windows IME/TSF; локализация меню и лупа touch selection.
- [x] Grapheme-aware editing, базовые multiline/password и валидация полей.
- [ ] Полноценная работа с текстом: shaping, fallback шрифтов, выделение/курсор.
- [x] Unicode 17.0.0: границы графем для стрелок/удаления/hit testing и default word boundaries для выделения; официальные conformance-тесты.
- [x] HarfBuzz: общие shaped runs, fallback Devanagari/Arabic/Hebrew/Symbols2 и построчный SheenBidi; лигатуры/диакритика, ограниченный кеш.
- [ ] Bidi-контекст абзаца через переносы, двойная affinity каретки, полный UAX #14.
- [x] Базовые semantics/actions, Windows UIA Invoke/Value/Scroll и Android virtual nodes; границы этапа: `BeastSDK/Source/UI/TextFeatures.md`.
- [ ] Accessibility/semantics, фокус и навигация.
  Нужны живые проверки Narrator/TalkBack, Windows TextPattern и offscreen-навигация.
- [ ] Расширение набора стандартных контролов и анимаций после стабилизации
  производительности существующих экранов.
