# Атлас глифов — 2026-09-14

## Условия

Windows, AMD Radeon(TM) Graphics, MSVC Debug, окно 540×650, DPI 1.25.
OpenGL 4.6 / Vulkan; vsync и validation выключены, profiling включён.
60 кадров прогрева + 120 измеряемых кадров на режим. Один последовательный
прогон без других GPU-тестов; для Vulkan порядок on/off обращён.
Это диагностические значения одной машины, не гарантии FPS и не Release-замеры.

Сравнивается текущий Canvas с атласом и тот же код с бюджетом атласа 0,
то есть прежним кешем целых строк. `build` — CPU-запись Canvas/BuildFrame,
`submit` — CPU-время RHI Submit, `GPU` — доступный асинхронный GPU timestamp.
GPU-интервал не включает все загрузки ресурсов, presentation и задержку ввода.
Текст, его размер и сцена между режимами одинаковы. RepaintBoundary в EcoScroll
остаётся включённым в обоих режимах.

## Результаты

Медиана / p95, миллисекунды:

| Сценарий | API | Атлас | Build CPU | Submit CPU | GPU |
|---|---|---|---|---|---|
| 24 меняющиеся подписи | OpenGL | off | 12.728 / 13.540 | 0.476 / 0.502 | 0.240 / 0.243 |
| 24 меняющиеся подписи | OpenGL | on | 1.601 / 2.195 | 0.272 / 0.544 | 0.052 / 0.057 |
| 24 меняющиеся подписи | Vulkan | off | 12.835 / 15.099 | 23.042 / 24.147 | 0.219 / 0.235 |
| 24 меняющиеся подписи | Vulkan | on | 1.655 / 2.570 | 0.514 / 0.831 | 0.277 / 0.319 |
| Скролл главной EcoSbor | OpenGL | off | 1.119 / 1.726 | 0.333 / 0.641 | 1.093 / 1.174 |
| Скролл главной EcoSbor | OpenGL | on | 1.242 / 1.853 | 0.313 / 0.651 | 1.078 / 1.176 |
| Скролл главной EcoSbor | Vulkan | off | 1.050 / 1.397 | 0.499 / 0.877 | 0.912 / 1.090 |
| Скролл главной EcoSbor | Vulkan | on | 1.257 / 1.725 | 0.477 / 0.904 | 0.895 / 1.051 |

В меняющихся подписях после прогрева:

- Build CPU быстрее в 7.8–8 раз; root draw calls за 120 кадров: 2880 → 120
  (24 → 1 на кадр). Новые bitmap handles: 2880 → 0; их CPU payload: 63,033,600 → 0 байт.
- Атлас не растеризовал новых глифов и не создал новых версий страниц:
  47,760 glyph hits, 0 misses. Удерживается одна страница 262,144 байта.
- Большой выигрыш Vulkan Submit связан с устранением потока новых текстур:
  существующий backend загружает их отдельными синхронными transfer-submit.
  Это не означает аналогичного ускорения шейдеров: GPU-медиана здесь немного выросла.

В EcoScroll новые текстуры после прогрева отсутствовали **в обоих режимах**.
Атлас дал 24,156 hits / 0 misses, удерживал 524,288 байт, но root draw calls
выросли с 6207 до 6651. CPU-подготовка стала дороже примерно на 0.12–0.21 ms
(11–20% медианы). Готовые раскладки/UV кешируются, однако геометрия отдельных
глифов дороже одного quad готовой строки. GPU-время в этом прогоне почти не
изменилось. Поэтому ускорение меняющегося текста нельзя выдавать за ускорение
скролла всей EcoSbor. Дальнейшее кеширование готовой геометрии — отдельная задача.

Root counters не включают содержимое вложенных слоёв. Счётчики atlas versions
учитывают copy-on-write, а retained bytes — только текущие страницы кеша;
старые версии могут удерживаться снимками/списками команд. Это не измерение VRAM.

## Воспроизведение и проверки

Из корня репозитория, в PowerShell:

```powershell
.\BuildTool\bin\Beast.BuildTool.exe build Test/EcoSbor --platform Windows --config Debug
.\Test\EcoSbor\Tests\Run-TextAtlasBench.ps1
.\BeastSDK\Tests\Run-UIShapeTests.ps1
.\Test\EcoSbor\Tests\Run-Tests.ps1
```

Лог замеров: `Intermediate/Verification/TextAtlasBench.log`.
`UIGlyphAtlasTests` сравнивает CPU coverage с прежним независимым растеризатором:
9 масштабов, 3 шрифта, дробные позиции, kerning, combining marks и некорректный
UTF-8. Максимальная обнаруженная разница — 1/255; реальный OpenGL readback
также дал максимум 1/255. Это результат проверенных сцен, не доказательство
пиксельной идентичности любого текста или Flutter.

Проверяются неизменяемость старых страниц при дополнении атласа, повторный
кадр, ограничения памяти, eviction, прозрачный fallback, nested layers,
replay и пересоздание RHI. Vulkan проходит runtime/validation без pixel readback.
Android APK-сборка проверяет компиляцию/упаковку; эти Windows-замеры не описывают
производительность Android-устройства.
