# Beast UI — кнопки и компоновка

## Canvas, слои и короткий запуск приложения

Обычному UI-приложению достаточно сцены и одной регистрации. Окно, RHI,
Android surface lifecycle, ввод, Back/Escape и запросы перерисовки обслуживает SDK:

```cpp
#include "Beast.h"

class MyScene final : public Beast::UI::Scene {
public:
    MyScene() {
        using namespace Beast::UI;
        using namespace Beast::UI::Build;
        ui.SetRoot(Centered(Make<Text>("Hello, Beast!", 24.f)));
    }
};
BEAST_UI_APPLICATION(MyScene, {.title = "My App", .width = 430, .height = 820,
    .backend = Beast::RHIBackend::OpenGL})
```

Макрос используется один раз, вне namespace; он создаёт обычный
`SceneApplication<MyScene>`. При необходимости остаются доступны исходные
`UI::Application` и `Beast::Application`. `AppOptions` содержит title, width,
height, backend, vsync и validation. Размер задаёт Windows-окно; Android
использует системную поверхность и safe area, не окно 430×820.

`UI/Build.h` предоставляет необязательные типизированные функции `Make<T>`,
`Box`, `Inset`, `Sized`, `Centered`, `Fill`, `Space`, `VBox`, `HBox`, `Scaffold`.
Последний собирает ограниченный по ширине экран с header, растягиваемым body
и bottom bar. Это обычные shared_ptr-виджеты с прежним single-parent ownership;
стили и бизнес-логика не скрываются в SDK. Общие builders из EcoSbor перенесены
сюда; приложение сохраняет свои Label, палитру, данные и обработчики.

В `Widget::OnPaint(Canvas&)` доступны:

```cpp
canvas.Save();
canvas.Translate(20, 30);
canvas.Scale(1.25f);
canvas.ClipRRect({0, 0, 180, 80}, 16);
canvas.RoundedRect({0, 0, 180, 80}, 0, {0, .5f, .3f, 1});
canvas.Text({12, 12}, "Hello", 18, {1, 1, 1, 1});
canvas.Restore();

canvas.SaveLayer({0, 0, 200, 100}, .5f);
// Все элементы группы рисуются со своими обычными цветами.
canvas.Restore(); // Общая прозрачность применяется ровно один раз.
```

- `Save/Restore` сохраняют clip и transform; `ClipRRect` требует открытый Save.
  `SaveLayer` сам выполняет Save. Все scopes должны быть закрыты до End.
- `ClipRect` — прямоугольный hard clip; `ClipRRect` маскирует готовую группу
  с аналитическим сглаживанием, а не каждый её элемент отдельно.
- `Translate` и положительный равномерный `Scale` — paint-only трансформации.
  Они не изменяют layout/hit testing. Комбинированный scale ограничен 1/16..16;
  rotation, skew, произвольная матрица и `ClipPath` ещё не реализованы.
- Слои RGBA8 создаются в физических пикселях после DPI/transform, без уменьшения
  разрешения и повторной фильтрации текста. Все вложения используют пиксельную
  сетку корневого окна, включая округление половинных координат. Слой обрезается
  по bounds и текущему clip; bounds ограничивают также glow/shadow.
- Готовые виджеты `ClipRRect(child, radius)` и `Opacity(child, alpha)` позволяют
  обходиться без собственного paint-кода. Rounded clip учитывается pointer hit
  testing. Opacity=0 не отключает ввод; при необходимости отключайте сам контрол.
  Opacity=1 не выделяет offscreen target, но сохраняет тот же bounds clip.
- До 8 вложенных GPU-слоёв, 32 сохранений состояния, 4096×4096 на слой,
  256 MiB суммарно на кадр. Не добавляйте слой к каждому Container автоматически:
  прозрачность обычного цвета и фон с радиусом дешевле отдельного framebuffer.
- RHI хранит неизменяемые снимки слоёв, повторно использует готовый GPU-результат
  при replay того же списка и восстанавливает его после пересоздания RHI.
  Перезапись сцены создаёт новые снимки; свободная GPU-память слоёв теперь
  переиспользуется ограниченным пулом (см. RHI/README.md). Автоматический
  кеш поддеревьев включается через RepaintBoundary (ниже); локальная перерисовка
  framebuffer и frame scheduling остаются отдельными этапами.

`UILayerTests.cpp` проверяет настоящие OpenGL-пиксели на 9 DPI, наложение цветов,
group alpha, вложенные слои/clip, crop, текст 1:1, replay и пересоздание RHI;
Vulkan проверяется исполнением с validation, без pixel readback. Запуск включён
в `Run-UIShapeTests.ps1`. Android использует тот же Canvas и GLES/Vulkan RHI;
сборка APK не заменяет проверку на устройстве.

Для диагностики короткий запуск принимает `.profiling = true` в AppOptions.
`UI::Application::GetRenderStats()` возвращает снимок CPU/GPU-метрик и счётчиков
пула (без активной поверхности — пустой снимок). Это opt-in диагностика, не HUD
и не вывод на каждом кадре. Benchmark EcoSbor измеряет построение UI отдельно
от CPU Submit и GPU timestamps; в обычном приложении новые строки кода для
переиспользования памяти слоёв не нужны.

## RepaintBoundary — кеш отрисовки поддерева

```cpp
using namespace Beast::UI::Build;
auto card = Cached(Box(VBox({Make<Text>("Hello"), Make<Button>("Tap", [] {})}), style));
// Эквивалент: Make<Beast::UI::RepaintBoundary>(child).
```

`Cached(child)` не меняет размеры, hit testing или правила clipping. Снимок RGBA8
создаётся в физических пикселях, затем выводится 1:1. Повторный paint неизменной
ветки не вызывает её OnPaint и не растеризует GPU-слой заново. Widget::Tick и
обработка ввода продолжают работать; это не замораживание виджетов.

SetText/SetStyle и другие setters помечают ветку и её предков. Тики анимации,
ripple, hover, keyboard focus, отмена ввода, layout, DPI, тема и paint transform
также учитываются. При целочисленном физическом переносе во время скролла
готовый слой переиспользуется; при изменении фазы текста он записывается заново.
После пересоздания RHI CPU-снимок восстанавливает GPU-ресурс автоматически.

Особенности первого этапа:

- Кешируйте отдельные относительно статичные карточки, а не весь ScrollView.
  Частично скрытые viewport карточки рисуются напрямую: изменение края обрезки
  не должно создавать новый framebuffer каждый кадр. Последний полный снимок
  остаётся доступен при обратном скролле, пока не вытеснен из кеша.
- Кеш не обрезает тени по layout box. Стандартный Container сообщает их размер
  через GetPaintBounds. Custom Widget с внешними декоративными эффектами должен
  переопределить GetPaintBounds и включить в результат весь видимый overflow
  в координатах layout. Изменяемое состояние custom widget должно вызывать
  Invalidate/InvalidatePaint либо возвращать true из OnTick. OnPaint не должен
  менять состояние приложения и обязан балансировать Canvas scopes.
- По умолчанию до 32 MiB консервативно посчитанных snapshot graph bytes и до 64
  записей на Context; LRU-вытеснение и weak ownership. Учитываются RGBA targets,
  достижимые bitmap-текстуры и команды/вершины, но не overhead драйвера/allocator.
  Это не общий лимит памяти GPU: текущий кадр, внешний replay, текстовый кеш и
  свободный RHI pool имеют собственные ссылки и бюджеты.
- `ui.SetRepaintCacheBudget(bytes)` задаёт 0–64 MiB, 0 отключает кеш;
  `ui.GetRepaintCacheStats()` возвращает hits, misses, bypasses, evictions,
  cachedBytes, entries. Размер одного кешируемого RGBA target — до 8 MiB и
  4096 пикселей по стороне. Превышение приводит к обычному paint, не уменьшению
  разрешения. Для nested RepaintBoundary записывается внешний снимок; внутри
  существующего SaveLayer/ClipRRect raster cache пропускается. Слишком глубокая
  группа также рисуется напрямую, сохраняя прежний предел 8 GPU-слоёв.
- Произвольный Canvas::Translate на дробное число физических пикселей пока
  рисуется напрямую: фаза текста 1/64 px недостаточна для точного определения
  всех переходов snap-rounded геометрии. Целочисленные Canvas-переносы и
  штатный ScrollView с пиксельной коррекцией используют кеш.

EcoSbor использует Cached для баннера, совета дня и карточек гида. Это ещё не
damage tracking: итоговый framebuffer по-прежнему очищается и компонуется целиком.
Атлас глифов описан ниже; Android Choreographer подключён для API 29+.
Virtualization и полный Flutter API пока не реализованы.
Измерения и ограничения — в Test/EcoSbor/Performance.md.

`UIRepaintTests.cpp` проверяет scoped invalidation, input/animation, budgets,
scroll, transforms и восстановление после неправильного custom painter.
OpenGL readback сравнивает кадры с кешем/без кеша при 9 DPI, включая text,
shadow overflow, fractional scroll и вложенную opacity. Vulkan проверяется
с validation и пересозданием RHI, без pixel readback. Тест включён в
`BeastSDK/Tests/Run-UIShapeTests.ps1`.

## Аналитические контуры и ripple, 2026-09-13

- RoundedRect/GradientRect используют покрытие площади физического пикселя,
  без фиксированной полигональной аппроксимации дуг. Внешние границы фона
  привязаны к единой пиксельной сетке с hard clipping; логический layout не меняется.
  Оба конца scissor округляются одинаково: соседние области не оставляют дыр
  и не перекрываются. Это **hard clip**, не произвольный subpixel/path clip.
  SDF быстро отсеивает полностью внутренние/внешние пиксели. На контуре
  восемь интеграционных сечений уточняют покрытие по более пологой оси;
  весь кадр не масштабируется и не размывается. Это численное приближение
  площади, проверяемое независимо по 512 сечениям; не дополнительный MSAA.
- Border — внутренняя обводка с дополнительными параметрами `borderWidth` и
  `borderColor` у методов Canvas. Покрытие заливки и обводки вычисляется одним
  шейдером, поэтому поддерживаются прозрачный центр и полупрозрачные цвета.
  Дуги/тонкие обводки сглаживаются аналитически; общий MSAA не включён.
- Button и Pressable автоматически показывают ripple от точки нажатия;
  клавиатура запускает его из центра. Расширение 450 мс, затухание 220 мс,
  отмена 90 мс. Быстрый tap между кадрами не теряется, длинное удержание после
  расширения не инвалидирует кадр постоянно. Одновременно хранится до четырёх
  волн. Scroll, потеря фокуса/поверхности, disable и удаление учитываются SDK.
- Ripple обрезается аналитическим пересечением окружности и скруглённой формы.
  `Pressable(child, callback, optionalRadius)` берёт радиус непосредственного
  Container-ребёнка либо 0; третий аргумент позволяет задать его явно.
  Это собственная реализация эффекта, не порт Flutter InkSparkle.
- Тени/glow рисуются одним проходом с непрерывным Gaussian falloff по SDF,
  sigma = shadowBlur / 2; область рисования расширена на 4 sigma. При blur=0
  остаётся чёткий смещённый силуэт. Это приближение размытия rounded rect,
  не общий blur фильтр/точная двумерная Gaussian-свёртка произвольного слоя.
  Декоративная тень не обрезается промежуточными layout bounds, но учитывает
  окно/safe area, все ScrollView и явные Canvas::PushClip. Обычное содержимое
  и hit testing сохраняют прежние границы. Для custom viewport следует
  вызывать PushClip/PopClip, а не полагаться на неявную обрезку Widget.

Проверки: `BeastSDK/Tests/Run-UIShapeTests.ps1` (сначала собрать EcoSbor Debug).
9 DPI от 75% до 400%, реальные OpenGL-пиксели против независимого area-reference,
стыки, прозрачные/тонкие/толстые бордеры, ripple и отмена ввода; overflow/falloff
теней через layout bounds и их обрезка ScrollView; Vulkan execution/validation.
`Run-UITests.ps1` отдельно проверяет, что текст остался с отображением 1:1.
Обрезка произвольных детей по пути и damage tracking остаются отдельными этапами.
Android frame pacing описан в `Test/EcoSbor/AndroidFramePacing.md`.

## Дополнение: перенос ЭкоСбор, 2026-09-12

Пример `Test/EcoSbor` добавляет следующие общие компоненты SDK:

- `Paragraph(text, ParagraphStyle)`: перенос по пробелам/UTF-8 символам,
  явные переводы строки, выравнивание, maxLines/ellipsis, Regular/Bold.
  Это простой перенос, не Unicode line breaking, shaping или rich text.
- `Icon(codepoint, size, color)`: небольшой Material Icons subset из прототипа,
  с Apache-уведомлениями. Отсутствующий codepoint вызывает исключение.
- `Pressable(child, callback)`: произвольный дочерний контрол с тем же вводом,
  фокусом и отменой нажатия, что у Button.
- `ScrollView(child, Axis, ScrollPhysics)`: обе оси, конечный viewport обязателен;
  wheel, Shift+wheel, drag/touch, захват по доминирующей оси и инерция.
  По умолчанию `Bouncing`: сопротивление за краем и пружинный возврат, в том
  числе у короткого содержимого. `Clamping` можно выбрать явно. Нет scrollbar,
  виртуализации или полной gesture arena. Tab теперь пропускает полностью
  обрезанные контролы; автопрокрутки к невидимому focus target пока нет.
- `ContainerStyle`: gradient, borderColor/borderWidth, shadowColor/shadowBlur/
  shadowOffset. Тени приближённые, ограничены явным clipping/viewport. Border поддерживает
  прозрачную заливку. Скругление детей по-прежнему не клипует.

Эти пункты уточняют ограничения предыдущего этапа ниже. `Text` остался
однострочным для совместимости; многострочный UI использует `Paragraph`.
Проверки и ограничения переноса — `Test/EcoSbor/README.md`.

Собственный C++ UI внутри одной библиотеки Beast, без отдельных Build.cs-модулей
SDK и без зависимости от Flutter/Dart. На Windows и Android дерево, layout,
hit testing, шрифт и paint-код общие; ОС предоставляет окно, события и DPI,
RHI — OpenGL 4.6 / OpenGL ES 3 либо Vulkan.

Ориентир — [подход Flutter к layout](https://docs.flutter.dev/resources/architectural-overview)
и [FilledButton](https://api.flutter.dev/flutter/material/FilledButton-class.html).
Это не совместимая реализация Flutter API и не точная копия Material 3.
Здесь retained-дерево: Widget объединяет состояние, измерение и рисование;
отдельных Widget/Element/RenderObject, reconciliation и hot reload пока нет.

## Подключение

`#include "Beast.h"` уже включает `UI/UI.h`. Создавайте дерево один раз,
храните Context и меняйте свойства через setters, не пересоздавайте его каждый кадр.

```cpp
using namespace Beast::UI;

Context ui; // Поле Application/сцены, не локальная переменная OnUpdate.
auto text = std::make_shared<Text>("Привет, Beast!", 18.0f);
auto button = std::make_shared<Button>("Нажми меня", [text] {
    text->SetText("Кнопка работает!");
});
auto column = std::make_shared<Column>(
    std::vector<WidgetPtr>{text, button}, 16.0f);
ui.SetRoot(std::make_shared<Padding>(24.0f,
    std::make_shared<Center>(column)));
```

Для нового UI-приложения используйте готовый host SDK:

```cpp
class MyScene : public Beast::UI::Scene {
public:
    MyScene() {
        ui.SetRoot(std::make_shared<Beast::UI::Center>(
            std::make_shared<Beast::UI::Text>("Hello, Beast!", 24.0f)));
    }
    // bool OnBack() override; // true = вернулись назад, false = выход.
};
class MyApp : public Beast::UI::Application {
    std::unique_ptr<Beast::UI::Scene> CreateScene() override {
        return std::make_unique<MyScene>();
    }
public:
    MyApp() : Beast::UI::Application({Beast::RHIBackend::Vulkan, true, false}) {}
};
BEAST_APPLICATION(MyApp)
```

`ConfigureWindow()` задаёт заголовок/размер, GPU-режим включается автоматически.
SDK владеет RHI, передаёт ввод в Context, обрабатывает Escape/Back, прекращает
рисование при Suspended и пересоздаёт RHI на SurfaceCreated. Scene/Context и
состояние экрана сохраняются между поверхностями. `Scene::OnUpdate` — логика
экрана; `Scene::OnEvent` — необработанный ввод/события; навигация — `Scene::OnBack`.
Повтор KeyDown не вызывает повторного Back. Android KeyUp больше не закрывает
приложение в обход навигации. На корневом экране Back по умолчанию завершает app.
Готовый пример: `Test/EcoSbor/Source/Launch/Launch.cpp`; генератор `beast new`
использует этот же подход. Низкоуровневый `Beast::Application` сохранён для
собственных render loops; пример ручного lifecycle — `Test/ButtonDemo`.
Callbacks, изменение дерева, layout и рисование выполняются на потоке Application.
Context не потокобезопасен. Не захватывайте owning shared_ptr самой кнопки в её
callback: это создаёт цикл владения; используйте weak_ptr или владельца сцены.

### Упругая прокрутка и стоимость кадра

`BeginDrag/DragBy` временно допускают отрицательный offset или offset выше extent.
`Fling(velocityDpPerSecond)` отпускает жест с инерцией; пружина точно возвращает
его к границе. `Stop()` останавливает движение и возвращает offset в диапазон.
Context сам вызывает эти методы для мыши/касания. Отмена касания запускает возврат,
потеря фокуса/поверхности и resize останавливают движение. Скорость берётся из
нативных временных меток ввода, для синтетических событий есть steady-clock fallback.
`SetOffset/ScrollBy` и дискретное колесо остаются ограниченными диапазоном.
Поведение вдохновлено [BouncingScrollPhysics](https://api.flutter.dev/flutter/widgets/BouncingScrollPhysics-class.html),
но это собственная физика, не побитовая копия Flutter и не widget `Flexible`.

Перемещение не вызывает Measure/Layout всего дерева: меняются позиции поддерева
и paint. Рисуемый слой выравнивается по физическим пикселям, включая вложенные
ScrollView; hit testing остаётся в dp (разница со snapping не более половины
пикселя на слой). Нет масштабирования текста: AA-текстуры отображаются 1:1.
Clipping не входит в ключ текстовой текстуры. Недавно видимые строки сохраняются
в ограниченном кэше (16 MiB / 512 записей после End); ресурсы текущих команд и
GPU-команд в полёте могут временно потреблять память сверх этого лимита.
Списки пока eager, без виртуализации. Это оптимизация текущего UI, не гарантия
постоянного FPS для произвольного размера дерева.

## Дерево и layout

- Узлы создаются через `make_shared`. Один узел имеет не более одного родителя
  и одного Context. Циклы, повторное присоединение и null-дети отклоняются.
- `Constraints`: допустимые min/max размеры. Родитель задаёт ограничения,
  ребёнок возвращает Size, родитель размещает его через Layout.
- `Padding` — одинаковый отступ со всех сторон; `Center` заполняет ограниченную
  область и центрирует ребёнка. `Row`/`Column` располагают детей по горизонтали/
  вертикали, `Expanded` делит свободное место; `Container` задаёт размеры и фон.
- Все размеры и координаты дерева — логические единицы (dp). `Window.scale`
  переводит их в физические пиксели. `Window.content*` задаёт безопасную область:
  кнопки не попадают под status/navigation bars Android.
- Rect дочернего узла задаётся в абсолютных логических координатах содержимого.
  Каждый узел обрезается своими bounds и bounds предков. Переполнение Flex
  обрезается; прокрутка добавляется через ScrollView, перенос — через Paragraph.
  Автоматического уменьшения текста нет.
- SetText/SetEnabled/SetOnPressed, SetFlex/SetOptions/SetStyle, изменение дерева и темы инвалидируют layout
  и paint. Неизменный экран повторно использует записанный RHICommandList.

### Row, Column, Expanded

Общий алгоритм `Flex(Axis, children, FlexOptions)` используется обоими классами.
Сначала измеряются обычные дети, затем оставшееся место после них и `spacing`
делится между `Expanded` пропорционально положительному весу `flex`:

```cpp
auto left = std::make_shared<Expanded>(
    std::make_shared<Button>("Левая", [] {}), 1u);
auto right = std::make_shared<Expanded>(
    std::make_shared<Button>("Правая", [] {}), 2u);
auto row = std::make_shared<Row>(std::vector<WidgetPtr>{left, right}, 12.0f);
// При ограниченной ширине Row кнопки получают 1/3 и 2/3 оставшейся ширины.
left->SetFlex(2); right->SetFlex(1); // Перекомпоновка следующего кадра.
```

- `FlexOptions`: spacing; `MainAxisSize::Min/Max`; `MainAxisAlignment`:
  Start, Center, End, SpaceBetween, SpaceAround, SpaceEvenly;
  `CrossAxisAlignment`: Start, Center, End, Stretch.
- Главная ось Row — X, Column — Y. Start — слева/сверху, End — справа/снизу.
  Reverse, RTL и baseline пока не поддерживаются.
- По умолчанию: spacing 12 dp, размер Min, основное выравнивание Start,
  поперечное Center. Старый `Column(children, spacing)` сохраняет поведение.
  В отличие от Flutter, основной размер по умолчанию не Max.
- Min сжимается до детей, Max заполняет конечный максимум родителя; с Expanded
  заполняется конечный максимум и при Min. Жёсткий размер родителя имеет приоритет.
  SpaceBetween/Around/Evenly распределяют свободное место **сверх** spacing.
- Expanded — непосредственный ребёнок Row/Column/Flex, его собственный ребёнок
  получает жёсткий размер по главной оси. Варианта Flexible с loose-fit пока нет.
- Главная ось с Expanded должна быть ограничена. Обычный ребёнок Flex измеряется
  по главной оси без верхней границы: вложенный Row с Expanded внутри другого Row
  нужно самому обернуть в Expanded или ограничить Container.width. Аналогично
  для Column/height. Неверная комбинация выдаёт исключение с объяснением.
- Stretch требует конечного размера поперечной оси; например, растянутому Row
  внутри Column может понадобиться Container с заданной высотой.
- При нехватке места Expanded получает нулевой остаток; обычные дети не сжимаются.
  `GetOverflow()` после layout возвращает превышение по главной оси в dp.
  Содержимое обрезается, без автоматического переноса или прокрутки.

Модель ограничений вдохновлена [Flutter Flex](https://api.flutter.dev/flutter/widgets/Flex-class.html),
но Beast пока не воспроизводит весь набор его режимов и диагностики.

### Container

```cpp
ContainerStyle style;
style.constraints.maxWidth = 640.0f;
style.padding = EdgeInsets::Symmetric(20.0f, 12.0f);
style.background = Beast::RHIColor{.12f, .10f, .15f, 1.0f};
style.cornerRadius = 24.0f;
auto panel = std::make_shared<Container>(row, style);
```

`width/height` необязательны. Они ограничиваются собственными `constraints`,
после чего ограничения предков имеют приоритет, даже при конфликте размеров.
`EdgeInsets` задаёт left/top/right/bottom; есть All и Symmetric.
`alignment` — необязательное одно из девяти положений от TopLeft до BottomRight:
оно заполняет ограниченные оси и размещает ребёнка внутри padding.
Без alignment Container подбирает размер по ребёнку с учётом своих ограничений.
Пустой Container без собственных ограничений заполняет конечную доступную область;
по неограниченной оси сжимается до padding. Отступы больше размера дают нулевую
область содержимого, не отрицательные размеры.

`SetStyle` проверяет значения и инвалидирует layout/paint. Скругление относится
только к фону: обрезка детей пока прямоугольная. Нет margin, общего rounded clip
или CSS/Flutter-совместимой системы стилей. Child задаётся при создании.

## Button

`Button(label, onPressed)` рисуется нашим Canvas, не нативным контролом ОС.
Пустой callback или `SetEnabled(false)` отключает кнопку.

- Предпочтительный hit target не меньше 48 dp по высоте; визуальная заливка
  имеет вертикальный inset 4 dp и скругления 20 dp. Жёсткие ограничения родителя
  могут уменьшить этот размер. Шрифт кнопки пока фиксирован — 14 dp.
- Hover имеет плавный переход 120 мс, pressed запускает ripple (см. выше).
  Keyboard focus обозначается обводкой; disabled использует приглушённые цвета.
  Это не полная Material animation system.
- Левый клик/касание активирует callback на отпускание внутри кнопки, один раз.
  Уход мыши наружу с отпусканием отменяет клик. Touch-сдвиг больше 18 dp отменяет
  tap целиком; лишние пальцы не перехватывают активный жест.
- Потеря фокуса, mouse capture, поверхности, переход в фон, смена viewport/DPI,
  отключение/удаление кнопки отменяют незавершённое нажатие. Изменение bounds
  активной кнопки при перекомпоновке также отменяет pointer/keyboard-нажатие;
  изменение только цвета, не затрагивающее bounds, сохраняет его.
- Tab и Shift+Tab обходят активные кнопки в порядке дерева, пропуская disabled.
  Space/Enter активируют выбранную кнопку при отпускании; key repeat не дублирует
  callback. Пока обход не исключает узлы, оказавшиеся вне clip при переполнении.
- Callback может безопасно удалить кнопку или заменить корень дерева: input
  state очищается до его вызова. Уничтожать сам Context внутри callback нельзя.

`Context::HandleEvent` возвращает true для обработанного UI ввода. Это позволяет
приложению не передавать такой ввод в другие интерактивные подсистемы.
Тема задаётся `Context::SetTheme(Theme)` и пока содержит только четыре цвета.

## Отрисовка и текст

`UI/Canvas.h` — API рисования для собственных Widget::OnPaint:
RoundedRect, Text и стек прямоугольных clips. Используйте Canvas, полученный
в OnPaint; Context управляет его Begin/End. Цвета API — straight RGBA [0,1],
Canvas переводит их в premultiplied alpha. Скругления — треугольники с
однопиксельной сглаживающей границей, текст — текстура coverage; соседние команды
с одинаковой текстурой и clip объединяются. Depth и native UI API не используются.

Один HLSL `Private/UI.hlsl` заранее преобразован нашим ShaderCompiler в SPIR-V,
GLSL 460 и GLSL ES 300, встроенные в `UIShaders.generated.h`. Поэтому обычной
сборке UI-приложения не нужны внешние shader tools; они требуются только при
изменении встроенного шейдера. CPU handles переживают пересоздание RHI,
native shader/texture/PSO ресурсы создаются новым backend заново.

Встроены доверенные Noto Sans Regular/Bold и Material Icons, без зависимости от
системных шрифтов. stb_truetype растеризует глифы в CPU-памяти; общий атлас
переиспользует их между строками. Готовые раскладки строк также кешируются.
Обычная латиница/кириллица, метрики и kerning работают одинаково на обеих ОС.

### Атлас глифов

Включён автоматически для `Text`, `Paragraph`, `Icon`, кнопок и custom
`Canvas::Text`. В Launch/Scene ничего добавлять не нужно. Один Canvas владеет
атласом всех трёх шрифтов; backend получает обычные RGBA8-текстуры и triangle-list.
Соседние глифы одной страницы с одинаковым scissor объединяются в draw call,
не меняя порядка прозрачной композиции.

- Ключ: индекс глифа, FontFace, точный физический em и фаза каждого глифа
  с шагом 1/256 px. Начало строки сохраняет сетку 1/64 px. Нет округления em
  или масштабирования низкоразрешённого bitmap: тексель соответствует пикселю.
- Страницы обычно 256×256, для крупных глифов увеличиваются по степеням двойки
  до 1024×1024. Между глифами прозрачные поля; фильтр Nearest сохраняет
  уже рассчитанное сглаживание. Упаковка полочная, без перемещения живых UV.
- Страницы запечатываются в `Canvas::End`. Если в следующем кадре на страницу
  добавляется глиф, создаётся новая копия страницы. Старые command lists и
  RepaintBoundary сохраняют неизменяемое изображение; новый RHI может восстановить
  его из CPU-данных. Незавершённые страницы нельзя отправить на GPU.
- По умолчанию удерживается до 16 MiB / 64 логических страниц; вытесняются
  давно не использованные страницы. Новые версии ограничены 16 MiB за кадр
  или меньшим заданным бюджетом. После кадра удержание укладывается в бюджет.
  Кеш раскладок/UV отдельно ограничен 512 строками и 2 MiB учтённых данных.
  Служебная память контейнеров и страницы, удерживаемые внешними снимками/командами,
  не входят в эти бюджеты. CPU-данные и native GPU allocations — разные расходы.
- Крупные глифы, исчерпание бюджета и перекрывающиеся полупрозрачные глифы
  используют прежнюю растеризацию целой строки. Последнее сохраняет исходную
  alpha-композицию. Этот fallback-кеш ограничен 512 строками / 16 MiB.

Диагностика, необязательная для приложения:

```cpp
ui.SetGlyphAtlasBudget(8ull * 1024 * 1024); // Context; максимум 64 MiB
auto textStats = ui.GetTextCacheStats();
// 0 отключает атлас для сравнения с прежним растеризатором строк.
```

`glyphHits/Misses`, `runHits/Misses`, `pagesCreated`, `sealedBytes`, `evictions`
и `fallbackLines` — накопительные счётчики. `pagesCreated` считает также новые
copy-on-write версии, `sealedBytes` — CPU payload запечатанных версий, **не**
измеренный трафик GPU. `pageBytes/pages/glyphs/runBytes/runs` — текущее состояние
кеша. Изменение бюджета не удаляет снимки из отдельного RepaintBoundary-кеша.

Это первый RGBA8 atlas, не R8/SDF/MSDF. При изменении страницы существующий RHI
загружает целую новую текстуру; частичные GPU uploads пока не реализованы.
Основной выигрыш — меняющийся текст из уже известных глифов. Статичная строка
раньше рисовалась одним quad, теперь требует геометрию на каждый глиф: ускорения
всего UI/скролла это само по себе не гарантирует.

`UIGlyphAtlasTests` сравнивает атлас с прежней CPU-растеризацией и реальными
OpenGL-пикселями на 9 DPI, проверяет три шрифта, дробные положения, clipping,
alpha, вложенные слои, eviction, replay и пересоздание RHI. Vulkan проверяется
с validation без pixel readback. Замеры — в `Test/EcoSbor/TextAtlasPerformance.md`.

### Чёткость и DPI

Физический размер равен `fontSize * Window.scale`, без округления em вверх:
например, 14 dp при 125% растеризуются именно как 17,5 px. Дробное положение
строки учитывается самим растеризатором с шагом 1/64 физического пикселя.
Готовый bitmap выводится на целочисленные границы экрана строго 1:1;
`Nearest` для этой текстуры сохраняет уже рассчитанное grayscale-сглаживание,
не смешивая его повторно с соседними текселями. Для обычных RHI-текстур
настройка фильтра не менялась. Layout и hit testing по-прежнему работают в dp.

При смене DPI/viewport Context инвалидирует кадр, кеш использует новый размер
и фазу растеризации. Старого ограничения 256 физических пикселей с последующим
растягиванием больше нет. Округлённые кнопки уже рисуются геометрией в разрешении
текущего framebuffer; весь UI не увеличивается из фиксированной low-res картинки.

Это устраняет повторное масштабирование внутри Beast, но не отключает естественное
сглаживание границ. Встроенный stb-шрифт пока без hinting/ClearType. Масштабирование
окна эмулятора, скриншота, удалённого рабочего стола или вывод монитора не в родном
разрешении могут добавить собственную фильтрацию, не контролируемую UI-движком.

Ограничения одного `Canvas::Text`: одна строка, до 4096 UTF-8 байт, размер 1–256 dp,
device scale до 16, физический em до 4096 px. Один bitmap ограничен 4096×4096 px
и доступной областью: превышение обрезается, а не сжимается/растягивается;
тайлинг очень длинных/крупных строк пока не реализован. Некорректный UTF-8 и
отсутствующие глифы заменяются U+FFFD, управляющие символы — пробелом.
Нет shaping/лигатур сложных письменностей, bidi/RTL, цветных emoji, fallback
шрифтов, rich text, selection, редактирования, IME и системного text scaling.
Перенос и ellipsis реализованы отдельно в `Paragraph`, не в растеризаторе глифов.
stb не получает произвольные файлы шрифтов: он не рассчитан на недоверенный ввод.

### Базовые переходы состояний

Для дробного движения списка без масштабирования снимка страницы:

```cpp
scroll->SetRasterization(ScrollRasterization::Subpixel);
```

По умолчанию остаётся PixelAligned для совместимости. EcoSbor включает Subpixel
для страниц и горизонтальной статистики. В этом режиме фигуры рисуются напрямую,
RepaintBoundary внутри списка обходит кеш снимков, глифы используют нативные
coverage-варианты с фазой 1/8 физического пикселя и Nearest 1:1. Это не bilinear
сдвиг растрового слоя. Цена — заполнение кеша фаз при первых движениях; режим
не гарантирует отсутствие холодных задержек. Прямоугольный GPU scissor остаётся
целочисленным, полноценный дробный clip этим изменением не добавлен.

Button и Pressable автоматически анимируют hover (120 ms), видимый keyboard
focus (150 ms), нажатие (80 ms) и отпускание (180 ms). Ripple ограничен формой
контрола; затухание использует smoothstep. Размер hit target не анимируется,
фокус не сдвигает подпись кнопки. Это общий код для обоих RHI.

Для появления/исчезновения группы используйте существующий Opacity:

```cpp
auto panel = std::make_shared<Beast::UI::Opacity>(content, 0.f);
panel->AnimateTo(1.f);       // 180 ms, ease-out
panel->AnimateTo(0.f, .12f); // прерывается от текущей прозрачности
panel->SetOpacity(1.f);     // немедленно, отменяет переход
```

Opacity=0 по-прежнему участвует в hit testing; для скрытия интерактивного
элемента управляйте его присутствием/доступностью отдельно. Промежуточная
прозрачность использует слой — не оборачивайте в неё без необходимости целую
длинную страницу. MotionValue доступен для собственных контролов: AnimateTo,
Tick, Get, Set. Завершённый переход не поддерживает бесконечную перерисовку.
Это базовые переходы, не полный набор анимаций навигации и раскрытия списков.

1. Scroll/List, общая система жестов и анимаций; Wrap и responsive-компоновка.
2. Расширяемые стили контролов, границы, тени и rounded clipping.
3. Полноценный текст: shaping, fallback шрифтов, IME и TextField.
4. Accessibility/semantics, навигация и сохранение состояния.
5. Платформенные адаптеры iOS/Linux/macOS; общий UI сам по себе не добавляет
   отсутствующие окна, ввод и графический backend этих ОС.

Проверки: `BeastSDK/Tests/UILayoutTests.cpp`, `UITests.cpp`, `UIRasterTests.cpp`, `Run-UITests.ps1` и
`Test/ButtonDemo/Verification.md`. Заявления о работе всех ОС и производительности
больших UI пока не делаем: текущий этап — Windows и Android, кнопки и компоновка.

### Idle-прогрев текста и touch sampling

`UI::Application` автоматически включает `Context::SetTextWarmupEnabled(true)`.
При ручном использовании Context прогрев включается явно. Он готовит 8 фаз
каждой оси Subpixel-scroll для видимых и ближайших коротких строк: до 128 UTF-8 bytes,
96 physical pixels font size, 128 ожидающих строк / 256 ключей. Большой/необычный
текст остаётся на обычном пути. Бюджеты atlas/run cache не увеличены.
За viewport резервируется половина его размера (максимум 256 логических единиц)
в обе стороны вдоль оси scroll. Обнаружение использует существующий обход дерева;
не более 64 невидимых подписей за paint. Обычные layout/explicit clips ограничивают
этот резерв внутри потомков, но реальные scissor, тени и drawing не расширяются.
Для вложенных scroll резерв консервативно ограничен родительским.
Одна порция имеет мягкую цель 750 μs с проверкой между глифами: незаконченная
фаза строки продолжается в следующий свободный кадр. Layout, один вызов
растеризатора, sealing и перепланирование ОС могут выйти за эту цель; это не
жёсткая гарантия времени кадра. Новые/COW страницы ограничены 512 KiB за порцию.
Выполняется только
в свободном кадре, не во время drag/animation. Законченный прогрев возвращает UI
к idle; новые DPI/строки/eviction могут потребовать обычной холодной растеризации.
После завершения движения один paint обнаруживает новый ближайший текст.
Первое действие сразу после запуска всё ещё может опередить прогрев; длинный
непрерывный fling может выйти за резерв. 256 ключей — лимит за время жизни
прогрева (сброс при смене DPI/бюджета), не неограниченная виртуализация списка.
Проверки: `BeastSDK/Tests/UIGlyphPrefetchTests.cpp` и `UIGlyphAtlasTests.cpp`.

Touch resampling использует `Window::frameTimeSeconds` в том же монотонном
домене, что `Event::timestamp`. При нулевом времени/невалидных событиях остаётся
прежний event-driven путь. Прогноз ограничен, не применяется к mouse/wheel и
отключается на release/cancel; hit testing и paint используют одну позицию.

При mouse/touch release первый шаг инерции/пружины ограничен временем от
`Event::timestamp` до текущего кадра. Время кадра до отпускания не интегрируется
повторно; событие новее frame timestamp ожидает следующего кадра. Ограничение
касается только физики scroll, не дочерних UI-анимаций. Regrab, Stop и новый
программный Fling отменяют старую привязку времени. Без общего frame clock
ручной Context сохраняет обычный шаг `deltaSeconds`.

Скорость жеста при неподвижном удержании сохраняется первые 20 ms, затем плавно
затухает до нуля к 80 ms: отпускание после паузы не должно заново толкать список
наружу. Mouse hover не активируется на кнопках во время drag.

### Редактируемый текст

Первый `TextField`, его API, демо и ограничения описаны в [TextField.md](TextField.md).
Это пока однострочный редактор committed input; Android IME, shaping и native
accessibility остаются отдельными этапами.

### Кеш размеров текста

`MeasureText` сохраняет точные результаты для неизменяемых встроенных шрифтов.
Ключ: UTF-8 строка, точные биты размера и FontFace; положение и scroll phase
размеров строки не меняют. Отдельный кеш на поток, без общих блокировок:
128 наборов по 4 записи, строки до 512 bytes. Более длинные строки измеряются
обычным путём; замещение ограничено четырьмя кандидатами, без обхода всего кеша.
Кеш не содержит текстур, не меняет растеризацию, округление или обработку UTF-8.
Проверки: `BeastSDK/Tests/UITextMetricsTests.cpp` и EcoSbor `Tests/Run-Tests.ps1`.
